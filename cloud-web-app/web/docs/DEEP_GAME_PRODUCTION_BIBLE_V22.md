# Deep Game Production Bible V22

Status: internal production contract. The UI remains compact, but agents receive a deep structure before heavy work.

## Purpose

The compact Production Bible is the user-facing cover. The Deep Production Bible is the production memory for agents. It prevents generic prompts from becoming incoherent games by binding story, world, characters, gameplay, scenes, asset quality, audio, runtime, playtest, and release evidence into one contract.

## Internal Depth

- Story architecture: premise, conflict, emotional arc, continuity rules, narrative risks.
- World contract: rules, biomes, factions, landmarks, traversal, streaming cells, navmesh plan, environmental storytelling.
- Character contracts: role, silhouette, motivation, gameplay function, animation, voice, relationships, evidence.
- Gameplay contract: 10-second loop, 2-minute loop, 20-minute loop, camera/input feel, progression, failure recovery, telemetry.
- Scene beats: purpose, player objective, emotional beat, location, required assets, animation, audio, camera language, transitions, failure states, performance budget.
- Asset quality: hero assets, environment kits, material rules, sourcing, LOD, rigging, proof.
- Runtime quality: Browser preview/review, Studio Local heavy production, Cloud Stream final review when configured.
- Agent handoffs: what each agent reads, writes, and must not do.
- Evidence model: blocked claims, required evidence, human approval checkpoints.

## UX Rule

Do not expose the whole bible as a wall of text. Studio and Evidence Center show counts, pillars, and the next decision. Details are for agent context, evidence, and review.

## Completion Rule

The Deep Bible can make agents smarter, but it cannot make work done. A game is not complete without build evidence, playtest replay, performance trace, asset provenance, rollback plan, and human review.
