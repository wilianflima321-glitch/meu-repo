## Why This Exists
This document replaces broad aspiration with a realistic 2026-2027 benchmark. The external V13 audit is treated as historical input, not as current repo truth. Its outdated debt numbers are intentionally not copied here because the current repo has already moved.

The current factual baseline is:
- `console.log/info/debug`: 0
- hardcoded hex in component TSX: 0
- explicit `: any` in app code: 0
- component files over 1000 lines: 0
- unit/spec tests: 87
- e2e specs: 15
- Prisma migrations: present
- Deploy UI: present
- Project Brain: present
- Mission Ledger: present
- Repository Cartography: present

The target is not to claim that Aethel beats every specialist tool in every specialist dimension. The target is to become the strongest unified web-first production workspace: Studio, IDE, agents, browser operator, preview, viewport, Project Brain, Mission Ledger, Repository Cartography, cloud/local runtime, and evidence-first release.

## Unique Aethel Advantage
Aethel's advantage is not one specialist feature. It is the union:
- Studio web-first entry
- real IDE depth
- agent fleet potential
- Project Brain
- Mission Ledger
- Repository Cartography
- browser operator governance
- game/film viewport depth
- deploy/release evidence
- cloud/local runtime routing

The strongest positioning is: Aethel is the agentic production Studio where apps, research, games, films, audio, browser work, and release evidence share the same mission memory.

## Critical Gaps To Prioritize
1. Agent Fleet + Repository Cartography must become visible and operational: agents need isolated sessions, handoffs, repo maps, diffs, evidence, cost, and rollback.
2. Studio Home must keep the Firebase/Replit-style mission entry clean while surfacing Project Brain, Mission Ledger, preview, device policy, and next action.
3. Game/Film mode must promote viewport, outliner, inspector, timeline, render/playtest evidence, and asset provenance.
4. Browser Operator must feel Manus-grade: plan, permission, replay, pause, takeover, risk labels, and evidence.
5. Design Canvas + Figma MCP parity must connect design reference, component mapping, code generation, and review without becoming a separate product.
6. Realtime collaboration/versioning must expose cursors, presence, agent worktrees, conflict review, and merge ownership.
7. Adobe-style creative media pipeline must add timeline/render queue/color/export discipline before any professional film claim.
8. Enterprise readiness must keep trust, audit, billing, margin, incident posture, and procurement proof factual.
9. Performance/monorepo scale must route huge repo scans through incremental indexing, external mirrors, and runtime workers.

## No-Overclaim Red Lines
- Do not claim Nanite, Lumen, Unreal parity, Premiere parity, Figma parity, Cursor parity, Manus parity, or autonomous AAA completion until the specific acceptance evidence exists.
- Do not call external source downloads safe until license/provenance and external-mirror metadata are reviewed.
